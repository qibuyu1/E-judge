# 风险评分与外部基准审计说明（v9.1.0）

## 1. 面向谁作判断

系统的核心问题不是“网上有没有负面新闻”，而是：

> 站在银行授信与企业合作方角度，这家企业当前是否具备可接受的偿债、履约与交易可靠性？

因此，结论同时给出银行授信和企业合作两种视角，并明确额度、期限、增信、账期、付款保障和持续监测建议。

## 2. 正式分档

| 分数 | 等级 | 审查含义 |
|---:|---|---|
| 0–39.9 | 低风险 | 当前证据下相对可控，可进入常规审查 |
| 40–59.9 | 中风险 | 有实质关注事项，应有条件准入并控制敞口 |
| 60–100 | 高风险 | 重大信用压力明显，核验和增信前不宜新增无保障敞口 |

“证据不足”不是第四档，而是暂不具备可靠评分条件。

## 3. 自主分析链路

1. **主体核验**：锁定企业名称、信用代码、股票代码及关键身份字段，防止同名或关联公司串主体。
2. **证据归因**：所有风险、关系和财务事实绑定来源，模型输出不能覆盖已验证主体字段。
3. **状态判断**：区分未发生、已解除/已结案、持续/新增，避免只按关键词计分。
4. **五维评分**：司法 30%、股权 20%、关联交易 25%、信息披露 15%、经营偿债 10%。
5. **银行信用底线**：重大违约、失信、破产、重大审计异常、大额执行等不能被其他安静维度稀释。
6. **偿债压力测试**：连续亏损、杠杆、流动性、现金流、净资产、债务/货币资金覆盖和审计意见综合判断。
7. **三档判定**：只根据实际证据和确定性规则形成低/中/高结论。
8. **决策翻译**：分别转化为银行授信与企业合作建议。

## 4. 防误判规则

### 防止低风险误判为高风险

- “未发生违约”“不存在重大诉讼”“未被列为失信”等否定表达不按负面关键词计分。
- “已解除冻结”“已结案”“已清偿”“已兑付”等事项降低当前有效权重。
- 正常履行、合并范围内或日常经营形成的担保/关联交易不单独构成高风险。
- 模型给出的 severity 或 risk_level 只是输入，不能压过原文中的否定或已解决状态。

### 防止高风险误判为低风险

- 单笔重大且大额的诉讼/执行至少进入中风险审查；特别重大且高强度时进入高风险。
- 债务违约与失信/执行叠加时设置高风险底线。
- 多项高强度信号、持续亏损、高杠杆和资金覆盖严重不足时设置审慎下限。
- 央企/国资背景只能有限缓释，不能把实质信用风险降成低风险。

## 5. 外部专家表

外部专家表不打包进项目，也不在生产运行时读取。代码仅保留以下不含企业身份的审计摘要：

- 100 条人工标注；
- 等级分布：低 21、中 56、高 23；
- 类型分布覆盖对外担保、欠债、法律诉讼、股权变动。

### 为什么不按公司名称查表

“公司名称 → 人工等级”的直接映射会造成标签泄漏：系统看似 100% 命中，实际上没有分析企业事实。一旦企业状态变化、同名主体混淆或表中结论本身过时，就会出现低风险说成高风险、高风险说成低风险。

v9.1 明确禁止：

- 按公司名称直接取得等级；
- 将外部表行级标签打包进项目；
- 用风险类型平均值把分数推过阈值；
- 把“未检出”当作“风险不存在”。

外部表只用于人工抽样复核、分布检查和阈值讨论，不改变单家公司生产分数。

## 6. 可复核场景回归

运行：

```bash
python tools/run_benchmark_regression.py
```

场景覆盖：

- 正常履行的担保应为低风险；
- 否定/已解除事项不得误判高风险；
- 单笔重大且有金额的诉讼应进入中风险；
- 债务违约叠加执行/失信应为高风险；
- 连续亏损、高杠杆、债务远超现金应为高风险；
- 输出只能是低风险、中风险、高风险或证据不足。

这类回归检查的是“相同证据是否稳定得出相同结论”，比名称命中更能发现评分逻辑错误。
