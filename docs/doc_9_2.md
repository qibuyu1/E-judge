# 本版修改说明（8.4.1）

## 1. 根因修复

- 修复结构化来源仅按 URL 去重的问题。同一个 F10 页面中的“公司档案”“前十大股东”“参控股公司”现在作为独立证据保留，不会再只剩其中一类。
- 修复企业档案已经解析成功，却被后续模型文本覆盖的问题。股票代码绑定的结构化档案优先级高于自由文本抽取。
- 修复关系数量统计只计算关系终点、忽略股东等入向节点的问题。
- 修复 DeepSeek JSON 返回空内容、代码块、字段类型不一致、百分数置信度等情况导致三个结构化通道同时失败的问题。

## 2. 企业基础信息

上市公司股票代码会并行读取证券结构化档案与公开 F10 页面。除标签字段外，程序还从历史沿革和公司资料正文中确定性提取：

- 法定公司全称与证券简称；
- 统一社会信用代码；
- 法定代表人；
- 注册地址、注册资本、成立日期；
- 所属行业、经营范围、主要产品、官网；
- 控股股东与实际控制人。

结构化档案中的值不会被公告中的子公司、担保对象或模型生成的长句覆盖。

## 3. 关系覆盖率

- 并行读取最新前十大股东、前十大流通股东。
- 读取上市公司参控股公司表，保留主要全资子公司、控股子公司、参股公司、联营及合营企业。
- 关系图最多保留 48 条高价值结构化关系，再与公开搜索抽取到的关联交易、担保、司法和风险事件合并。
- 图谱改为多环、多跳布局，大规模关系不再全部堆在同一个圆环上。

## 4. DeepSeek 稳定性

- Flash 的 JSON 结构化请求至少执行一次自动修复重试。
- 自动提取被 Markdown 或说明文字包裹的首个完整 JSON 对象。
- 对常见字段别名、字符串数组、百分数、风险等级和 source_ids 做后端标准化。
- Flash 连续无法通过结构校验时，仅对失败通道使用 V4 Pro 非思考模式兜底；正常请求仍由 Flash 完成。
- 即使模型通道失败，结构化档案和确定性规则结果仍继续进入报告，不再退化为两节点空图。

## 5. 前端重构

- 风险等级使用真正的三角金字塔，不再是四个普通梯形卡片。
- 风险与建议采用等权的编辑式双栏排版，正文统一字号。
- 删除说明性小句、英文虚化大字和可见证据 ID。
- 决策链路改为轻量时间轨道，不再使用大块卡片。
- 整体深红背景略微提亮，减少沉重感。
- 关系图节点按控制、投资、交易、担保、风险等语义配色；高密度图谱自动缩小普通节点并保留高对比边标签。
