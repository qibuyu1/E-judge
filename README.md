# 链网E判 v9.5.3

面向银行对公授信与企业合作审查的企业公开信息、关联关系、经营偿债和履约风险分析系统。

## 页面结构

- `/`：品牌首页与企业查询页。
- `/report?report_id=...`：完整风险分析报告。
- 顶栏“历史查询”：只展示与当前评分版本一致的历史报告，旧版本报告自动失效，避免沿用旧评分和旧字段。


## v9.5.3 查询按钮与首屏修复

- “开始分析”按钮不再因 API 未配置而变成不可点击的灰色控件。
- API 未配置或后端未启动时，点击按钮会显示明确故障提示；配置完整时正常进入查询。
- 查询标题、输入框、三项能力卡整体上移，首屏空间更紧凑。
- 静态资源构建号已更新，避免浏览器继续加载旧版 JS/CSS。

## v9.5.2 核心原则

### 正式结论保持三档

- **低风险（0–39.9）**：当前公开证据下风险相对可控，可进入常规审查；不等于零风险。
- **中风险（40–59.9）**：存在需要核验的实质关注点，建议有条件准入并控制额度、期限、担保和账期。
- **高风险（60–100）**：已出现直接信用失败、严重审计异常、重大执行/失信/违约，或持续经营与偿债压力；落实核验和增信前不宜新增无保障敞口。

证据不足时显示“证据不足/待核验”，不会把缺失数据当作低风险，也不会仅凭企业名称、历史标签或行业印象决定风险。

### 防止高低风险倒置

v9.5.2 将“证据是否属于目标主体、是否仍然有效、是否直接影响偿债和履约”置于关键词和模型严重度之前：

- “未发生、无、未认定、已解除、已结案、已清偿、已整改”等状态会被识别，不再因出现“违约、诉讼、冻结”等词自动升高风险。
- 正常子公司关系、日常关联交易、合并范围内担保、一般股权变动不作为高风险依据。
- 同一风险被多个网页或抽取通道重复提及，按风险家族去重，避免重复加分。
- 关系企业自身的风险不得直接计入目标企业，只有目标企业承担责任或风险明确传导时才参与评分。
- 标准无保留审计意见、正利润、正经营现金流形成一致健康证据时，可限制无直接不利证据的误升档。
- 当前未清偿违约、失信、破产、重大执行、担保代偿、资金占用和严重审计异常仍保留高风险底线，健康指标不能覆盖直接信用失败。

### 银行授信视角

系统的结论围绕以下问题形成：

1. 是否存在当前、可归属于目标企业的直接信用失败；
2. 是否对偿债能力、现金流、资产安全或履约稳定形成实质压力；
3. 风险是历史已解决事项、一般经营事项，还是仍在持续的重大事项；
4. 银行应正常审查、有条件准入，还是暂停新增无保障敞口；
5. 企业合作方应采用何种账期、担保、分批交付和止损安排。

## v9.5.2 前端修复

- 查询页使用统一的酒红顶栏、暖白红工作区和酒红页脚，不再出现上下割裂的大块纯白空区。
- 顶栏 Logo 改为可见的白色六边形与酒红链形标识，深色背景下不再丢失。
- 企业基本信息增加后端字段清洗和前端最终显示保护，防止法定代表人、地址、经营范围、控股股东等字段串列。
- 报告页风险事项分布保留“重大、高、中、低”四段展示；四段共用同一斜率、仅留 2px 分隔，整体保持大尺寸可读。
- 雷达扫描、报告生成进度和分析置信度均显示实时百分比。
- 公开证据行悬停时保持深色文字与足够对比度，不再出现文字消失。

> 风险事项分布使用四段展示，企业最终信用结论仍严格保持低、中、高三档。

## API 配置

将 `.env.template` 复制为 `.env`，填写：

```env
TAVILY_API_KEY=你的Tavily_API_Key
DEEPSEEK_API_KEY=你的DeepSeek_API_Key
```

## 视频位置

将首页视频命名为 `hero-bg.mp4`，放入：

```text
frontend/assets/video/hero-bg.mp4
```

## Windows 启动

```text
1. 双击 install.bat
2. 配置 .env
3. 双击 check_config.bat
4. 双击 start_web.bat
```

访问 `http://127.0.0.1:8000`。

## 升级说明

建议解压到新目录，不直接覆盖旧版本。v9.5.2 的缓存模式版本为 `43`，程序会自动隐藏旧评分版本的历史报告；也可执行 `reset_cache.bat` 主动清理旧缓存。

用户提供的 `benchmark.xlsx` 不随项目分发、不在运行时读取，也不存在按企业名称查人工等级并强制改分的逻辑。
